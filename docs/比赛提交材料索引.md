## 二、建议答辩主线

系统不是固定 Agent 串联，也不是依赖超长上下文的自由群聊。核心主线是：

```text
高层意图和多文件输入
→ TaskSpec 与 Requirement Contract 冻结
→ 层级规划和阶段式动态图增长
→ 能力、历史表现与端边云约束联合路由
→ 直接依赖稀疏通信与分层记忆唤醒
→ 真实代码或工具执行
→ 证据核验与确定性业务验收
→ 失败归因、局部子图重放
→ 需求账本闭合后生成报告
```

Python 固定安全外壳独占状态推进、文件落盘、真实执行和最终成功判定；模型负责语义理解、
规划建议、专业推理、代码生成和报告表达。这一职责边界是系统鲁棒性的基础。

## 四、MathorCup 演示验收

重新执行：

```bash
python main.py --input examples/mathorcup_d
python utils/run_audit.py
```

只有审计命令返回退出码 0，且同时满足以下条件，才可在答辩中称为完整成功：

```text
run_state.outcome == success
run_state.finished == true
business_validation.status == passed
requirement_acceptance.status == passed
review.can_generate_final_report == true
evidence_verification.passed == true
final_report.md 存在
无 failed/blocked 节点
无未解决 blocking issue
```

当前实现已经针对历史真实失败补齐：

- 300 件货物数量、坐标、重叠、易碎、顶部间隙、载重、利用率和成本复算；
- 业务失败重新定位 code 节点并注入结构化错误；
- 模型修复耗尽后执行 TaskSpec 声明的领域代码插件；
- EvidenceVerifier 非法枚举、漏依赖和连接异常；
- 分阶段规划遗漏 code 节点时补充唯一交付节点；
- 多 code 职责收敛；
- 最后报告模型连接失败时从已验证证据生成报告。
